# Scroll-Assembled Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `index.html`'s single-screen hero into a scrolling page whose name, menu, and social links morph from the centered hero into a fixed left sidebar (hamburger drawer on mobile).

**Architecture:** All markup lives in `index.html`. Custom morph/layout CSS goes in `src/input.css` (compiled to `dist/output.css` via `npm run build-css`). Behavior is plain inline JS in `index.html`: one `requestAnimationFrame`-throttled scroll handler drives a `--p` CSS variable (0→1 across the hero height); an `IntersectionObserver` highlights the active section; a click handler toggles the mobile drawer. Degrades gracefully without JS and under `prefers-reduced-motion`.

**Tech Stack:** Tailwind CSS 3.3 + PostCSS (existing), Flowbite (existing), vanilla JS, no new dependencies.

## Global Constraints

- No new dependencies or build tooling beyond existing Tailwind/PostCSS. (verbatim: "No new dependencies or build tooling beyond the existing Tailwind/PostCSS setup.")
- Reuse existing theme only — no new color values. Use `font-libre`, existing theme colors, and `dark:` variants.
- Dark mode must work in hero, sidebar, and all four sections. Preserve auto-by-hour + manual toggle logic.
- Placeholders only for Projects/Writing — mark each with `<!-- TODO: replace placeholder -->`. No real project/post data.
- Only `index.html`, `src/input.css`, and rebuilt `dist/output.css` change. Do not touch other pages.
- After any CSS-class change, run `npm run build-css` so new utilities land in `dist/output.css`.
- Work on branch `feature/scroll-sidebar`. Commit after each task.

### Task 3: The scroll morph (desktop) + fallbacks

Drive `--p` from scroll position and interpolate the hero-out / sidebar-in motion. Add `prefers-reduced-motion` and no-JS fallbacks.

**Files:**
- Modify: `src/input.css` (extend the custom block)
- Modify: `index.html` (rewrite the inline `<script>`; add `class="no-js"` handling)

**Interfaces:**
- Consumes: `#hero`, `#sidebar`, `.hero-inner`, `:root --p` (from Tasks 1–2).
- Produces: `document.documentElement` gains class `js` when scripting is on; `body` gains class `scrolled` when `--p > 0.05`.

- [ ] **Step 1: Add morph CSS (desktop only)**

Append to the custom block in `src/input.css`:

```css
@media (min-width: 768px) {
  /* Hero copy fades and lifts as you scroll */
  .hero-inner {
    opacity: calc(1 - var(--p));
    transform: translateY(calc(var(--p) * -32px));
  }
  /* Sidebar travels in from the left; name scales up */
  html.js #sidebar {
    opacity: var(--p);
    transform: translateX(calc((var(--p) - 1) * 40px));
    pointer-events: none;
  }
  html.js body.scrolled #sidebar { pointer-events: auto; }
}

/* Fallbacks: no JS or reduced motion -> sidebar docked, hero static */
html:not(.js) #sidebar { opacity: 1; transform: none; }
@media (prefers-reduced-motion: reduce) {
  .hero-inner { opacity: 1 !important; transform: none !important; }
  html.js #sidebar { opacity: 1 !important; transform: none !important; pointer-events: auto !important; }
}
```

- [ ] **Step 2: Rewrite the inline `<script>`**

Replace the existing first inline `<script>` block (the fade-in + dark-mode + menu-toggle + scroll-hide logic, current lines ~114–161) with:

```html
<script>
  const root = document.documentElement;
  root.classList.add('js');

  // Dark mode: auto by hour, plus manual toggle
  const hour = new Date().getHours();
  if (hour >= 19 || hour < 7) root.classList.add('dark');
  document.getElementById('dark-toggle')
    .addEventListener('click', () => root.classList.toggle('dark'));

  // Scroll-driven morph: --p goes 0 -> 1 across the hero height
  const hero = document.getElementById('hero');
  function updateProgress() {
    const h = hero.offsetHeight || window.innerHeight;
    const p = Math.min(Math.max(window.scrollY / h, 0), 1);
    root.style.setProperty('--p', p);
    document.body.classList.toggle('scrolled', p > 0.05);
  }
  let ticking = false;
  window.addEventListener('scroll', () => {
    if (!ticking) {
      requestAnimationFrame(() => { updateProgress(); ticking = false; });
      ticking = true;
    }
  }, { passive: true });
  updateProgress();
</script>
```

> Removes the obsolete "hide dark toggle on scroll" logic (the toggle now lives in the sidebar) and the old `fade-in-up` script. Leave the Flowbite and Vercel `<script>` tags below it untouched. The `.fade-in-up` `<style>` block and any leftover `fade-in-up` classes can be removed if present.

Run: `npm run build-css`
Expected: completes without errors.

- [ ] **Step 2: Add the IntersectionObserver**

Append inside the rewritten `<script>` from Task 3 (before its closing `</script>`):

```javascript
  // Highlight the active section in the TOC
  const tocLinks = Array.from(document.querySelectorAll('.toc a[data-nav]'));
  const byId = id => tocLinks.find(a => a.dataset.nav === id);
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        tocLinks.forEach(a => a.classList.remove('active'));
        const link = byId(entry.target.id);
        if (link) link.classList.add('active');
      }
    });
  }, { rootMargin: '-40% 0px -55% 0px', threshold: 0 });
  ['about', 'projects', 'writing', 'contact']
    .map(id => document.getElementById(id))
    .filter(Boolean)
    .forEach(sec => observer.observe(sec));
```
